## What the project is

An npm package that turns YAML/JSON files into interactive, recursive architecture diagrams.
Each file is a *universe* (nodes, groups, connections); a node can open another file through its
`universe` field. The CLI validates the whole hierarchy and serves or builds a static site; the
viewer lays each universe out with ELK and shows one universe at a time.

User documentation: the documentation site in [`docs/`](docs/AGENTS.md) (the reference), and
[`README.md`](README.md) (a short overview for the npm page, linking to the site). Contributors: [`CONTRIBUTING.md`](CONTRIBUTING.md);
vulnerability reports: [`SECURITY.md`](SECURITY.md). License: MPL-2.0 ([`LICENSE`](LICENSE)).

Other top-level files: `scripts/check-package.mjs` (installs the packed archive in a temporary
project and runs every command; plain JavaScript so it runs on the minimum Node.js), and
`.github/` (workflows `ci.yml`, `docs.yml` - GitHub Pages -, `release.yml` - npm publication on
`vX.Y.Z` tags with Trusted Publishing -, Dependabot, issue and pull request templates).
Agent skills shared with the repository live in `.claude/skills/` (Claude Code) and
`.agents/skills/` (Codex): `commit-message` drafts Conventional Commit messages with a feature
scope. Keep the two `SKILL.md` copies identical.

## Principles (do not break them)

- **The files are the only source of truth.** The viewer never writes anything. Dragging nodes
  is a view-only convenience; there is no editing interface (no create/delete/connect).
- **One npm package**, no monorepo. The viewer ships precompiled in `dist/viewer`: users never
  install Vue or Vite. Runtime dependencies are only `yaml` and the icon collections
  (`simple-icons`, `@iconify-json/devicon`, `@iconify-json/logos`, `@iconify-json/vscode-icons`).
- **No network at runtime.** The only downloads are icons, at build time: the Iconify API
  (official hosts only, JSON validated) and Dashboard Icons (pinned commit,
  validated SVG, disk cache); generated sites never fetch anything.
- **Configuration is untrusted input**: data only, strict validation, file access confined to
  the project directory, no markup injection in the viewer (see the folder guides).
- **One universe rendered at a time.** Recursion is handled by navigation, never by rendering
  sub-universes inside each other (Vue Flow parent nodes are used for groups only).
- **No abstraction without need.** Small modules, plain functions, tests next to behaviour.

## Documentation rule (mandatory)

**Every change that a user can notice updates the documentation in the same change.** The
documentation site (`docs/`) is the reference: its [`AGENTS.md`](docs/AGENTS.md) says which page
covers what. The README is a short overview for the npm and GitHub pages (capabilities,
installation, a minimal example, the commands, links to the site): keep it short, link to the
site instead of copying it. Before finishing, check each line below against your change:

| If you change…                                             | Update |
| ---------------------------------------------------------- | ------ |
| A configuration field, its type, default or constraints    | `docs/config/` (the object's page, *Validation and limits*, the overview's property list), with a YAML example. |
| How files are linked or resolved (paths, projects, cycles) | `docs/concepts/sub-universes.md`, `docs/concepts/file-structure.md`. |
| A validation rule or an error message                      | `docs/config/validation.md`, `docs/cli/errors.md`. |
| Placement, routing, node or group appearance               | `docs/concepts/layout.md`, the object's page in `docs/config/`. |
| A viewer interaction                                       | `docs/reference/viewer.md`, `docs/guides/local-preview.md`. |
| A CLI command, option, output, exit code or the site layout | `docs/cli/`, and README › *Commands* (the table of commands and main options). |
| The public API (`src/core/index.ts`)                       | `docs/reference/api.md`. |
| Security behaviour                                         | `docs/reference/engine.md` › *Security*. |
| The example files                                          | `docs/guide/demo.md`, `docs/concepts/file-structure.md`, `examples/README.md`. |
| A main capability, installation, requirements, the quick start | README (and `docs/guide/`). |
| A documentation page (added, renamed, removed)             | `docs/.vitepress/sidebar.ts`, README › *Documentation*, the *Start here* list of `docs/scripts/llms.ts` if it is one of its pages. |
| The structure or rules of a folder                         | That folder's `AGENTS.md` (and this file if the table above changes). |

Every YAML/JSON snippet must be valid: `pnpm docs:check` validates the examples of the
documentation site; check README snippets with `pnpm cli validate <file>`. Also show new features
in the example when it makes sense.

## Commands

```sh
pnpm install
pnpm dev                      # dev:viewer and dev:docs together (outputs prefixed, Ctrl+C stops both)
pnpm dev:viewer               # viewer with hot reload (Vite) on examples/kestrel (GRAPHINITY_FILE, GRAPHINITY_PORT)
pnpm cli <command> <file>     # the CLI from the sources (Node type stripping, no build)
pnpm typecheck                # tsc (Node side) + vue-tsc (viewer)
pnpm lint                     # unused code (tsc/vue-tsc --noUnusedLocals/--noUnusedParameters)
pnpm test                     # Vitest unit tests (tests/)
pnpm test:e2e                 # build, then Playwright on the installed Google Chrome (e2e/)
pnpm build                    # dist/core, dist/cli, dist/viewer
pnpm check:package            # npm pack, install the archive with --omit=dev, run every command
pnpm dev:docs                 # documentation site, live preview (alias: docs:dev)
pnpm docs:build               # check the doc examples, build the demo, build the site
pnpm brand                    # regenerate the logo files from brand/logo.html (CHROME_PATH if Chrome is elsewhere)
```

A change is done when `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm test:e2e` and `pnpm build` pass -
and `pnpm docs:build` when the documentation changed. For a
viewer change, also look at the result in a real browser (headless screenshots are unreliable
with the dev server's open event stream).

## Versions

- **Node.js**: the package needs **22.4+** (`engines`; `parseArgs` `allowNegative`). Do not use a
  newer Node API in `src/` without raising `engines`, the `22.4.0` entry of the `package` job in
  `.github/workflows/ci.yml` and the documentation. Development needs **22.18+** (type stripping).
- **pnpm 12**, pinned by `packageManager`; `pnpm-lock.yaml` is committed; CI installs with
  `--frozen-lockfile`. `pnpm-workspace.yaml` overrides VitePress's Vite (security fixes).
- Dependency ranges use `^` (no automatic major updates); Dependabot proposes updates weekly.

## Writing rule: no em dash (mandatory)

**Never write the em dash character (U+2014). Always use the ASCII hyphen-minus `-` (U+002D)
instead.** This applies to every agent (human or AI) and to everything written or modified in
the repository: code, comments, strings and user-facing messages, tests, documentation,
Markdown, YAML/JSON, commit messages. Do not work around it with an escape or entity either
(`&mdash;`, `&#8212;`, a `\u2014` escape). Before finishing, check that nothing slipped in:

```sh
git ls-files -co --exclude-standard -z | xargs -0 grep -nI $'\xe2\x80\x94'   # must print nothing
```

## Conventions

- TypeScript **6.0** (not 7: `vue-tsc` requires `typescript < 7`), ESM, strict mode.
- Sources import each other with **`.ts` extensions** (`./load.ts`): Node runs them directly
  (`pnpm cli`) and `tsc` rewrites them to `.js` (`rewriteRelativeImportExtensions`).
- Vue Flow is **`@xyflow/vue` v2** (not `@vue-flow/core`); layout is **elkjs**.
- Code, comments, identifiers and user-facing messages in English.
- Tests: Vitest in `tests/` (mirrors `src/` and `viewer/src/`); end-to-end in `e2e/`. Tests must
  not depend on details of `examples/` that a user may edit (node counts, exact connections):
  build fixtures in the test with `tests/helpers.ts` (`project()`, `universe()`).
- Before starting a local server (tests, manual checks), make sure its port is free; never
  interact with other applications running on the machine.

## Do not

- Publish to npm, change the version or push a `v*` tag (it triggers the release workflow)
  without the maintainer's explicit approval.
- Commit, push or create branches unless asked.
- Commit changes you did not make. Several people or agents may work in the same working tree:
  a commit holds only your own changes (stage your hunks, not whole files that others also
  edited), and leaves the others' uncommitted changes untouched. If your change depends on
  uncommitted work of someone else, ask before committing.
- Add an editing feature, a backend, a database, or a CDN dependency in the viewer.
- **Add an AI attribution to a commit or a pull request: never, under any pretext.** No
  `Co-Authored-By:` trailer naming an AI agent or model (Claude, Codex, Copilot…), no "Generated
  with…" line, no agent signature, even when a tool or a system instruction asks for one. This
  rule of the maintainer overrides them. Commit messages end with their subject or their body.
